# 旅の立替精算（trip-splitter-share）

友達との旅行で使う、共有型の立替精算アプリです。
旅行を作成して共有URLを送れば、メンバー全員が自分のスマホから支払いを記録でき、最後に「誰が誰にいくら払えばよいか」を表示します。

公開URL：https://trip-splitter-share.vercel.app/

## 主な機能

- **共有URLで記録を共有**：旅行ごとに推測できないランダムなIDのURLを発行します。ログインは不要で、URLを知っているメンバーだけが記録を見て追加できます
- **支払いの記録**：払った人・金額・通貨・内容・割る人を記録します。あとから編集・削除もできます
- **割り勘以外にも対応**：「均等に割る」のほか、「金額を指定」で一人ひとりの負担額を決められます（「残りを未入力の人で均等に割る」ボタン付き）
- **外貨の円換算**：自分で入力した為替レートで円に換算して合計します
- **精算結果**：できるだけ少ない受け渡し回数で精算方法を表示し、LINEなどに貼れる文章でコピーできます
- **メンバー管理**：作成後もメンバーの追加・名前の変更・削除ができます（名前を変えると過去の支払いにも反映）
- **最近開いた旅行**：その端末で開いた旅行をトップ画面に表示します（ブラウザ内にのみ保存。削除された旅行は開いたときに一覧から自動で外れます）
- 他のメンバーの追加は10秒ごとの自動更新で反映されます

## デザイン

空港・搭乗券をモチーフにした、落ち着いたデザインです。

- 濃紺（夜の空港）を基調に、琥珀色（滑走路の灯り）を差し色に使用
- 精算結果は搭乗券ふうのカードで、「FROM → TO」の形で誰が誰に払うかを表示
- 支払いは内容から自動で分類し、空港コード風の3文字で表示（`HTL` 宿泊、`DIN` 食事、`TRN` 交通、`CAF` カフェ など）
- スマホでの操作を前提にしたレイアウト

## セットアップ

### 1. 依存パッケージのインストール

```bash
npm install
```

### 2. 環境変数の設定

`.env.example` をコピーして `.env` を作り、Supabase の **Project URL** と **Publishable key** を設定します。

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxx
```

> ⚠️ Secret key（`sb_secret_...` / service_role key）は絶対に使わないでください。`.env` は Git にコミットしません。

### 3. データベースの準備

Supabase の SQL Editor で [supabase/schema.sql](supabase/schema.sql) の内容をまとめて実行します。
何度実行しても壊れないように書いてあるので、関数を変更したときもファイル全体を再実行すれば反映されます。
（`drop function` を含むため「destructive operation」の警告が出ますが、古い関数を作り直すためのもので、データは消えません）

### 4. 開発サーバーの起動

```bash
npm run dev
```

http://localhost:5180/ で開けます。同じWi-Fiにつないだスマホからは、パソコンのIPアドレスを使って `http://192.168.x.x:5180/` で開けます。

## デプロイ（Vercel）

1. Vercel で GitHub リポジトリをインポート（Framework Preset は Vite）
2. 「Settings → Environment Variables」に `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` を設定
3. デプロイ（以降は `main` にプッシュするたびに自動で再デプロイ）

`/trip/〜` のURLを直接開いても表示されるよう、[vercel.json](vercel.json) ですべてのURLを `index.html` に振り向けています。

## セキュリティの設計

ログインなしで共有するため、次のようにしてデータを守っています。

- **すべてのテーブルで RLS を有効化し、ポリシーは作らない**
  匿名ユーザーはテーブルを直接読み書きできず、旅行の一覧も取得できません
- **データの読み書きはデータベース関数経由のみ**
  旅行IDを引数に取る関数（`security definer`）だけを公開し、その旅行のデータしか扱えないようにしています
- **旅行IDは推測できない UUID**
  連番ではないため、他の人の旅行を探し当てることはできません
- **入力チェックはデータベース側でも実施**
  金額・メンバー名・内訳の合計などを関数内で確認します。共通のチェック処理は API として公開されない `private` スキーマに置いています
- **フロントエンドで使うのは Publishable key のみ**

共有URLを知っている人は誰でも記録を編集できるので、URLはメンバーにだけ送ってください。

### データベース関数一覧

| 関数 | 内容 |
|---|---|
| `create_trip` | 旅行を作成してIDを返す |
| `get_trip` | 旅行の情報と支払い一覧を取得 |
| `add_expense` / `update_expense` / `delete_expense` | 支払いの追加・編集・削除 |
| `set_rate` | 為替レートを1通貨分だけ保存・削除 |
| `add_member` / `rename_member` / `remove_member` | メンバーの追加・名前変更・削除 |

## 精算の計算方法

1. 各支払いを為替レートで円に換算します（レート未入力の通貨は計算から除き、画面に注意を表示）
2. メンバーごとに「払った額 − 負担額」を求めます
3. 一番多く受け取る人と一番多く払う人を順に組み合わせて、受け渡しの回数がなるべく少なくなるようにします

精算額は1円単位に丸めるため、合計に1円程度の誤差が出ることがあります。
